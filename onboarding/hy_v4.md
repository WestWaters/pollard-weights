## Contributor notes (bot-lab-21, 2026-09-08) — things the audit cannot see from the index alone

- **Experts are stored fused.** Each MoE layer has two stacked tensors, `mlp.experts.gate_up_proj` `[256, 4096, 6144]` (12.9 GB bf16)
  and `mlp.experts.down_proj` `[256, 6144, 2048]` (6.4 GB), not `experts.N.{gate,up,down}_proj`. `FFN_PROJ` never matches, and the
  MoE export path needs a per-expert slice of dim 0. This is the transformers-5.16 `HYV4Experts` layout, likely to appear in other
  new MoE checkpoints too.
- **Model code lives only on transformers `main`** (`models/hy_v4`, added 2026-09-07; not in 5.16.1). No `auto_map` / remote code.
  Checkpoint names differ from module names via `WeightRenaming` rules in `conversion_mapping.py`: `hc_pre.hc_*` → `hc_*`,
  `learnable_sink_param` → `sinks`, `linear_gate` → `gate_proj`, `hc_attn_layer.*` → `attn_hc.*`, `hc_mlp_layer.*` → `ffn_hc.*`,
  `hc_head_*` → `hc_*`. Any tool matching on checkpoint names must handle both spellings.
- **Hyperconnections (`hc_mult` = 4).** The residual is four streams of `hidden_size`; activation memory for any streaming or
  band-parallel pass is 4× a conventional model of this width (768K calibration tokens × 4 × 6144 bf16 ≈ 39 GB). Band boundaries
  must hand off all four streams plus the DSA top-k of the last `"full"` indexer layer.
- **Attention output gate** (`linear_gate` → `gate_proj`, `gated_mla: true`): an elementwise sigmoid gate on the attention output,
  consumed from the same `input_layernorm` seam as `q_a_proj` / `kv_a_proj_with_mqa` / the indexer. Protect like a router.
- **Learnable attention sinks** (`sinks`, one per head, fp32-sensitive) and `enable_lm_head_fp32: true`.
- **DSA indexer sharing:** `indexer_types` = 21 `"full"` + 57 `"shared"` layers; shared layers reuse the previous full layer's
  top-k. `mlp_layer_types`: layer 0 dense (`intermediate_size` 18432), layers 1–77 sparse. One MTP layer under `model.mtp_layers.0.*`
  (not `model.layers.78`), with its own `eh_proj`/`enorm`/`hnorm`/`final_layernorm`.
- **Shard layout:** 131 shards, 1.56 TB bf16; tensor-name order, so a layer spans 6–16 shards (up to 34 GB) — per-layer staging is
  workable, whole-band staging is not, on a 128 GB node.
- **Calibration:** 384 × 2048 in-domain rows built through the model's own chat template (`reasoning_effort`-style template, vocab
  120,832, EOS 120025); held-out texts excluded by content hash.
- **Coming in this PR:** routing concentration per MoE layer (pick count + routing-weight mass over 786K tokens), per-channel |x|
  max at the two norm seams and the two latent seams (`q_a_layernorm`, `kv_a_layernorm`), hyperconnection gate statistics per
  stream, attention-gate and sink statistics, per-tensor weight statistics incl. per-expert norm spread, byte inventory by category,
  per-layer GB10 timings for `pollard-calc`, and a bf16 reference NLL on the calibration rows. Same streaming pass we used for
  GLM-5.3 (§F1/F2 of `notes/glm-5.3-744b-routing-and-smoothing-data.md`), running now on two DGX Sparks with the rows split.
